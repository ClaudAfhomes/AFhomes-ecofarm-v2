# Browser import review contract correction

The user requested a real browser test and removal of its synthetic import data. The first one-row Gold workbook upload on `claud/develop` Preview failed at `POST /api/v1/customer-imports/parse` with HTTP 500. No customer was committed. The failed job and its single row were removed using exact fixture identifiers after checking for protected business references; audit events were retained. An independent query confirmed zero remaining fixture jobs, rows, customers or sources.

Verified root cause: migration 16's continuation response includes a 64-character `expectedTeamVersion` hash. The API parses that response through a strict shared schema that omitted the key, producing `unrecognized_keys: expectedTeamVersion`. This happened after the parse endpoint saved its review job, explaining why database-only import RPC testing did not detect the HTTP failure. The tests' previous batch-RPC fixture omitted the same field and therefore did not model the real response.

The correction adds the required revision field to the response schema only. Request schemas remain unchanged, strict validation remains enabled, and database genealogy/stale-review checks remain authoritative. No migration or permission change is needed. The API batch fixture now includes the actual database field and the XLSX/XLSM parse tests assert it is retained in the normalized continuation preview. Those tests reproduced HTTP 500 before the schema correction and passed afterward. Typed UI continuation fixtures were synchronized.

Initial focused API verification: 85 tests across the customer-import handler, official-form transitions and canonical import-facts files passed. Workspace typechecks passed. UI verification, scoped lint and the deployed browser retry are recorded separately after execution. No real payment, receipt, membership, account or genealogy data belongs in the browser fixture. Browser testing is limited to disposable import/intake/draft application records; cleanup must stop if financial history or external references are found, retain audit events, and never reset the official ID counter.

Before the Preview retry, 50 UI tests across the import continuation, official-form and import/export screens passed. Scoped lint for all four changed TypeScript/test files passed with zero errors or warnings; one preexisting unused mock argument was removed. No SQL or applied migration file changed.
