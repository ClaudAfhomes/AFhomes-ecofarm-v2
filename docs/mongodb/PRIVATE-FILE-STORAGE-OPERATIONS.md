# Private file storage operations (local disk)

Private business files stay on the Droplet at
`/var/lib/afhomes/private-files`. MongoDB stores metadata, ownership, audit
records and object keys; it does not store the bytes. Public website media uses
`/var/lib/afhomes/media/public` and is served by Nginx. The two roots must never
overlap; startup rejects that configuration.

The same `PrivateObjectStore` interface and S3 implementation remain available.
Select exactly one provider:

```text
AFHOMES_PRIVATE_STORAGE_PROVIDER=local
AFHOMES_PRIVATE_STORAGE_ROOT=/var/lib/afhomes/private-files
```

`filesystem` is accepted as a compatibility alias for `local`. If the provider
is unset, private upload/download routes fail closed instead of falling back to
a development store.

## What uses this store

- Staff, IST, OST and customer profile photos (upload, replace, preview, remove)
- Government IDs and identity-review documents
- Payment proofs, receipts and Finance attachments
- Reservation agreements and signed contracts
- Customer and VIP documents
- Import files and payment-claim evidence
- Admin-uploaded business documents and other supported images/PDFs

All of these already call the shared store; no feature gets its own disk path.
Keys are generated by the server (`profile-photos/<owner>/<uuid>.jpg`,
`identity-documents/...`, `import-claims/...`, etc.) and are never taken from a
client filename.

## Environment

Add to `/etc/afhomes/api.env` (root-owned, mode `0600` or `0640` for a deploy
group; never `VITE_*`, never Git):

```sh
AFHOMES_PRIVATE_STORAGE_PROVIDER=local
AFHOMES_PRIVATE_STORAGE_ROOT=/var/lib/afhomes/private-files
# Optional hardening. Defaults are shown.
AFHOMES_PRIVATE_STORAGE_MAX_BYTES=16777216
AFHOMES_PRIVATE_STORAGE_MIN_FREE_BYTES=134217728
# Optional ClamAV-compatible scanner; receives the temporary file path.
# AFHOMES_PRIVATE_STORAGE_SCAN_COMMAND=/usr/bin/clamdscan
```

`BETTER_AUTH_SECRET` must be at least 32 characters. The store derives a
separate signing key from it; changing the secret invalidates outstanding
download grants but does not re-encrypt existing files.

## Directory setup

Run only during an approved deployment:

```sh
sudo install -d -m 0755 -o root -g root /var/lib/afhomes
sudo install -d -m 0700 -o afhomes -g afhomes /var/lib/afhomes/private-files
sudo -u afhomes test -r /var/lib/afhomes/private-files
sudo -u afhomes test -w /var/lib/afhomes/private-files
sudo -u afhomes test -x /var/lib/afhomes/private-files
```

The API user owns the root and files are `0600`; subdirectories are `0700`.
The service unit already grants `ReadWritePaths=/var/lib/afhomes`. Nginx must
not contain an `alias` or `root` pointing at this directory.

## Startup and runtime checks

`api/_server.ts` (the bundled production entrypoint) and `api/server.ts` both
accept the provider. On startup the local store:

1. requires an absolute root outside the application directory and outside the
   public media root;
2. creates the root if missing with mode `0700`;
3. verifies read/write/execute access;
4. checks free space against `AFHOMES_PRIVATE_STORAGE_MIN_FREE_BYTES`;
5. fails startup if the root is unusable, the provider is invalid, or free space
   is below the threshold.

Every write re-checks free space before publishing. A full disk returns an
upload error and leaves existing files untouched. `/ready` also reports the
store as not ready when capacity is exhausted.

Serving is limited to `GET /api/v1/private-files` with a short-lived HMAC token
(60–300 seconds, per object). Responses are `private, no-store`, use
`X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and
`Cross-Origin-Resource-Policy: same-origin`; non-images are attachments with a
sandbox CSP. The access token is in the query string, so Nginx and the API log
only the pathname, never the query.

## Optional malware scanning

Installing ClamAV is an operator decision; the repository does not add a paid
service or a new dependency. When `AFHOMES_PRIVATE_STORAGE_SCAN_COMMAND` is set
to an absolute executable, the store runs it with the temporary file path before
the file is published. A non-zero exit or timeout rejects the upload and removes
the temporary file. Keep the ClamAV signature database updated through the
distribution's normal service.

## Backup

Back up private files separately from public media and separately from the
MongoDB snapshot. Keep the only long-term copy of the backup key off the
Droplet.

```sh
# One-time, on the administrator workstation:
openssl rand -out afhomes-private-backup.key 32
chmod 600 afhomes-private-backup.key
```

For a consistent copy, stop the API during the archive (or use an approved
maintenance window). The archive is streamed to the workstation and encrypted
there, so the backup key never has to be stored on the Droplet:

```sh
stamp=$(date -u +%Y%m%dT%H%M%SZ)
ssh root@portal.afhomes.com.ph 'systemctl stop afhomes-api'
ssh root@portal.afhomes.com.ph 'tar -C /var/lib/afhomes/private-files -cpf - .' \
  | openssl enc -aes-256-cbc -pbkdf2 -salt \
      -pass file:./afhomes-private-backup.key \
      -out "afhomes-private-$stamp.tar.enc"
ssh root@portal.afhomes.com.ph 'systemctl start afhomes-api'
sha256sum "afhomes-private-$stamp.tar.enc" | tee "afhomes-private-$stamp.tar.enc.sha256"
```

Copy the `.tar.enc` and `.sha256` to the approved off-server location with
`scp`, `rsync` or the operator's existing backup tool. Do not upload the
archive to the public media root or a public bucket. The archive contains the
private bytes and the `.metadata` sidecars, not the public media tree.

Also snapshot the MongoDB metadata (Atlas snapshot or the approved
`mongodump`/local backup procedure). A file archive without matching ownership
and object-key records is not a restorable backup.

## Restore (isolated first)

```sh
stamp=20261103T120000Z
ssh root@portal.afhomes.com.ph \
  'install -d -m 0700 -o afhomes -g afhomes /var/lib/afhomes/private-files.restore'
openssl enc -d -aes-256-cbc -pbkdf2 \
  -pass file:./afhomes-private-backup.key \
  -in "afhomes-private-$stamp.tar.enc" \
  | ssh root@portal.afhomes.com.ph \
      'tar -C /var/lib/afhomes/private-files.restore -xpf -'
ssh root@portal.afhomes.com.ph \
  'chown -R afhomes:afhomes /var/lib/afhomes/private-files.restore'
ssh root@portal.afhomes.com.ph \
  'find /var/lib/afhomes/private-files.restore -type f -exec chmod 0600 {} +'
ssh root@portal.afhomes.com.ph \
  'find /var/lib/afhomes/private-files.restore -type d -exec chmod 0700 {} +'
```

Verify checksums and the reference audit against the restore directory before
switching:

```sh
ssh root@portal.afhomes.com.ph \
  'set -a; . /etc/afhomes/api.env; set +a; cd /srv/afhomes/current; AFHOMES_PRIVATE_STORAGE_ROOT=/var/lib/afhomes/private-files.restore pnpm private-files:audit'
```

Then, during an approved window:

```sh
ssh root@portal.afhomes.com.ph 'systemctl stop afhomes-api'
ssh root@portal.afhomes.com.ph \
  'mv /var/lib/afhomes/private-files /var/lib/afhomes/private-files.before-restore'
ssh root@portal.afhomes.com.ph \
  'mv /var/lib/afhomes/private-files.restore /var/lib/afhomes/private-files'
ssh root@portal.afhomes.com.ph 'systemctl start afhomes-api'
ssh root@portal.afhomes.com.ph 'curl -fsS http://127.0.0.1:3084/ready'
```

Rollback only the code release; never roll back the file directory or Mongo
records together with it. A code rollback keeps the files and metadata intact.
If the previous release only supports S3, leave the provider unset or configure
S3; private routes fail closed rather than reading a partial store.

## Read-only reference audit

```sh
pnpm private-files:audit
```

The command reads `profile_photos.object_key`, `identity_documents.storage_path`,
`customer_import_payment_claims.proof_path`, and legacy
`payments`/`reservation_agreements.receipt_storage_path` references. It reports
counts only (no keys, no PII) and exits non-zero when a referenced object is
missing or invalid. It does not modify MongoDB records or file bytes. Use it
before and after a restore, and after a migration file transfer.

## Deploy and rollback commands

The artifact build and release switch are unchanged:

```sh
pnpm install --frozen-lockfile
pnpm --filter api typecheck
pnpm --filter api exec vitest run _lib/private-object-store.spec.ts _lib/production-config.spec.ts --maxWorkers=1
pnpm --filter api build:artifact
sudo install -d -o afhomes -g afhomes /opt/afhomes/api/releases/<release-id>
sudo cp -R api/dist/. /opt/afhomes/api/releases/<release-id>/
sudo ln -sfn /opt/afhomes/api/releases/<release-id> /opt/afhomes/api/current
sudo systemctl restart afhomes-api
curl -fsS http://127.0.0.1:3084/health
curl -fsS http://127.0.0.1:3084/ready
```

Rollback:

```sh
sudo ln -sfn /opt/afhomes/api/releases/<previous-release> /opt/afhomes/api/current
sudo systemctl restart afhomes-api
curl -fsS http://127.0.0.1:3084/ready
```

## Remaining boundaries

- Existing legacy `receipt_storage_path` values that still point at Supabase
  buckets will be reported as missing until the approved file transfer links
  them. The audit does not invent or rewrite those references.
- `storage_cleanup_jobs` rows are deliberately retained for operator review;
  there is no automatic deletion worker. The audit reports the pending count.
- Public media backup is a separate procedure; do not mix the two archives.
- The scanner is optional and not installed by this repository. MIME/signature,
  size, extension and atomic-write checks run regardless.
